# 雪王拼豆 · Xuwang Pindou

把图片变成拼豆图纸的**纯前端小工具**：图片自动按 MARD 拼豆色卡配色 → 网格编辑器手改 → 导出可打印图纸 + 用豆清单。
零依赖、零构建，双击 `index.html` 就能用，也能丢到任何静态托管上，还能装到手机桌面离线使用。

> **关于图标**：应用图标是雪王风格的绘制（雪人 + 王冠 + 红围巾）。
> 「蜜雪冰城」及其雪王形象是**注册商标**，本项目与蜜雪冰城无任何关联。
> 自己装着玩没问题；**如果要公开发布或商用，请先换成不侵权的图标**（改 `assets/icon.svg` 后跑 `npm run icons` 即可）。

> 界面**不使用任何 emoji**：图标一律用文字标签（画笔 / 橡皮 / 吸管 / 填充 / 撤销 / 重做），避免不同系统字体下 emoji 变形、打印变黑白方块，以及读屏软件把图标念成奇怪的名字。`npm run test:dom` 里有一条测试专门守着这件事。

## 快速开始

```text
方式一（最省事）：双击 index.html
方式二（推荐，localStorage 自动保存与离线缓存一定可用）：
    npm run serve      # 然后打开 http://127.0.0.1:5179/
    # 或者： python -m http.server 5179
方式三（手机）：见下方「部署到手机」
```

> `file://` 打开时，部分浏览器会禁用 `localStorage`（自动保存）与 Service Worker（离线缓存），此时界面会提示改用「导出项目」手动保存，其余功能不受影响。

## 部署到手机（没有服务器也能用）

三条路，按推荐顺序：

### 方案 A：GitHub Pages 免费托管（推荐）

不需要买服务器，得到一个固定网址，手机电脑都能开，更新只要 push。
本项目已就绪：仓库名 **`xuwangpindou`**，发布地址 **https://qibao0619.github.io/xuwangpindou/** 。

**第一步：在 GitHub 建空仓库**

打开 https://github.com/new ，仓库名填 **`xuwangpindou`**，可见性选 **Public**，**不要**勾 "Add a README file"，直接 Create。

**第二步：把项目推上去**

在 `pindou` 目录里执行（`.gitignore` 已配好，`data/` 和 `dist/` 不会被传）：

cd pindou
git init
git add .

git remote add origin https://github.com/qibao0619/xuwangpindou.git

**第三步：开启 Pages**

仓库页面 **Settings → Pages**：
- `Source` 选 **Deploy from a branch**
- `Branch` 选 **`main`**，目录选 **`/ (root)`**
- 点 **Save**，等 1 分钟左右

**第四步：手机安装**

浏览器打开 **https://qibao0619.github.io/xuwangpindou/** ，然后：
- **Android Chrome**：右上角菜单 → **安装应用** / **添加到主屏幕**；
- **iPhone**：**必须用 Safari**（微信内置浏览器做不到）→ 底部分享按钮 → **添加到主屏幕**。

装完就有图标了，点开是全屏、无地址栏，而且**没网也能用**（Service Worker 已缓存整个应用）。

**以后更新**

改完代码只要 `git add . && git commit -m "说明" && git push`，Pages 会自动重新发布（约 1 分钟）。
手机上的版本会在下次联网打开时自动更新。

> ⚠️ 必须走 **HTTPS**（GitHub Pages 自带）或 **localhost**，Service Worker 和「安装应用」才会生效。
> 这也是为什么 `file://` 双击打开能用，却拿不到离线能力和桌面图标。

## 手机 / 平板上的用法

手机上界面会**自动换成另一套布局**（≤900px 触发），把主要功能留在手边，其余塞进「菜单」侧边栏：

- **顶部是生成区**：选图、格数（29 / 58 / 87 一键板数）、最多颜色数、去背景、生成按钮，够用就行；
- **生成完自动收起生成区**，并把预览区滚到眼前，不用自己往下翻；要重新生成点一下标题条展开；
- **预览图下方（竖屏）/ 右侧（横屏）是色块清单**：每种颜色一个色块，显示色号 + 颗数，**点一下就在图上高亮这个颜色**，再点取消；
- **双指缩放 / 平移**：画布上双指捏合缩放、双指整体拖动平移；单指拖动是平移画布而不是滚动页面；
- 画布设了 `touch-action: none`，手指在图上怎么划都不会误滚页面；桌面端想要更大范围再用工具栏的 `+` / `-` / 适配；
- **默认是预览模式**，手指乱摸也不会改图；要改先点「编辑」。

> 平板横屏（宽 620–1100px）会把色块清单放到**预览图右侧**，竖屏则放在**下方**，两种情况都不挡图。

## 预览模式（默认）与编辑模式

**打开就是预览模式**，只读，怎么拖都不会把图案改坏：

- 在画布上按下左键也**只会平移**，不会画上去；光标是「抓手」而不是十字，一眼就知道点不着；
- **撤销 / 重做 / 清空 / 旋转 / 翻转 / 裁边 / 去背景**这些按钮在预览模式下**直接隐藏**，工具栏不会挤一堆用不上的按钮；
- 用豆清单点行高亮、色卡标识、网格线、分板线、缩放平移**都能用** —— 看图该有的都有；
- 剩余可用的功能只有看：缩放 / 平移 / 高亮 / 显示开关。

要改图就点顶部的「**编辑**」（快捷键 `P` 来回切换）：

- 切过去后编辑类按钮才出现，工具栏出现画笔/橡皮/吸管/填充，光标变十字，左键即绘制；
- 不小心在预览模式下点了编辑类快捷键（`B`/`E`/`I`/`G`/`Ctrl+Z`），**一律忽略**，不会偷偷改图；
- 顶栏有明确的「预览模式 / 编辑模式」状态牌，不会搞不清自己在哪。

## 色卡：内置 MARD 真实色卡（221 / 291 色）

默认色卡就是 **MARD 拼豆的官方色号体系**，不是随便凑的颜色 —— 出图上的色号可以直接照着买豆：

| 内置色卡 | 内容 |
| --- | --- |
| **MARD 标准 221 色**（默认） | A 黄橙 26 · B 绿 32 · C 蓝 29 · D 紫 26 · E 粉 24 · F 红 25 · G 棕 21 · H 黑白灰 23 · M 浊色 15 |
| **MARD 完整 291 色** | 标准 221 + 扩展 70：P 肤色 23 · Q 荧光 5 · R 扩展色 28 · T 透明白 1 · Y 马卡龙 5 · ZG 珠光 8 |
| 新手常用 26 色 | 非品牌通用色，适合刚入门、豆子不全时先出图 |
| 通用全色系 221 色 | 非品牌，按色域自动铺匀的通用色 |
| 黑白灰 8 色 | 专门做单色/灰度图 |

MARD 色卡的特点：

- **色号与色名都来自真实色卡**：`A01 浅黄`、`B05 绿`、`ZG6 珠光蓝`、`T01 透明白`……和店家色号一致，买豆时直接报色号；
- **只在 221 色里配色就不会买到买不到的豆**：手里只有标准套装时选「标准 221 色」，别选 291（291 会用到 P/Q/R/T/Y/ZG 扩展色）；
- **色号搜索**：221/291 个色块靠眼睛找不到，色卡上方搜索框输 `B05`、`浅黄` 或 `#FAF4C8` 都能筛；
- **色卡下方有一行来源说明**：写明数据来自哪个源、以及「HEX 是屏幕近似值，实物以实物色卡为准」；
- 「最多颜色数」上限已放宽到 **999**，填 250 之类的值不会被截断；
- 性能：MARD 221 量化 200×200（4 万像素）实测普通约 4ms、开抖动约 12ms，不吃性能。

**覆盖率实测**（`npm run probe`，随机 4000 色到最近色卡色的平均 ΔE）：MARD 221 ≈ **9.28**、MARD 291 ≈ 9.25、新手常用 26 色 ≈ 14.93、自动铺匀的通用 221 色 ≈ 5.86。
注意最后一行：通用色卡是「按色域铺匀」优化出来的，ΔE 必然更低；**但它的色号买不到**。MARD 色卡的 ΔE 是真实色卡本身的离散度决定的，这才是能落地的选择。

#### 色卡数据从哪来 / 怎么更新

色号数据不是手抄的，是抓取后由脚本生成、并且有校验的：

```bash
npm run data:fetch     # 抓 webfem / pixel-beads / 公开汇总仓库三份原始数据到 data/
npm run data:build     # 校验并生成 js/palettes/mard.js（默认用 webfem 那份）
npm run data:build -- --source=pixel-beads   # 也可以换成别的源
```

- 默认数据源：[webfem MARD 色号表](https://webfem.com/tools/pindou/mard-color-chart/)（291 色，带色名，源数据更新于 2026-08-20）；
- 生成时会校验：总色数 291 = 标准 221 + 扩展 70、15 个系列色数逐个对得上、色号不重复、色值格式合法；
- 珠光 ZG 系列在源页面是多色渐变卡片（`background-color` 写的是白色），脚本取渐变色均值作为单一屏幕近似值，否则 8 个珠光色会全变成白色；
- 抓不到网络也能用：`js/palettes/mard.js` 已生成并入库，运行时**不联网**。

> ⚠️ **务必知道的三个坑**：
> 1. **HEX 只是屏幕近似值**，不是官方光谱测量值。显示器、环境光、批次都会偏色，买豆以店家色号和实物色卡为准；
> 2. **公开数据源之间是有差异的**。以本机实测：webfem 与公开汇总仓库版 291 色里 274 个色值不同（平均三通道差 9.9，最大 77）；webfem 与 pixel-beads 版 165 个不同（平均 33.2，最大 282，后者在 Q/B/C 几处疑似错位）。想让图纸严格对齐你手上那套豆，**以实物色卡为准**；换源只需上面那条 `--source=` 命令；
> 3. 色名来自数据源（如「浅黄」「珠光蓝」），用于你辨认颜色，不是品牌官方商品名。

### 颜色是怎么配的

1. 图片按格数**逐级折半降采样**（不是直接硬缩，避免大片锯齿）；
2. 每个格子取平均色 → 转 **CIELab** → 在色卡里找 **CIE76 色差最小**的颜色（比直接比 RGB 符合人眼得多）；
3. 可选 **Floyd–Steinberg 抖动**（渐变更顺滑，但豆子会变碎、用量变大）；
4. 可选 **限色**：见下一节，按「相近色合并、阴影阶压缩、差异大的保留」的规则压到 N 色。

### 限色：相近颜色并成一色，但该保留的一个不少

「最多颜色数」填了 N 之后，用的不是「谁面积大留谁」，而是**反复合并代价最小的一对颜色**，直到色数降到 N：

- **判断标准分两类**：
  - **色相/彩度差异**（Lab 的 a、b 分量）→ 代价高，尽量不合并，所以红色、绿色这类真正不一样的颜色会被保留到最后；
  - **明度差异**（Lab 的 L 分量，也就是高光/阴影层次）→ 代价便宜，同一色相下的深浅阶优先并成一色，**过渡阴影被压掉**，只留下最有代表性的那一阶；
- 所以结果是「**相近的用同色、阴影面积减少、差异大的保留**」，而不是把一整片蓝色画成 4 个几乎一样的蓝、却把 2 格的红眼睛涂成蓝色；
- **黑↔白这类明度差过大的颜色有硬上限，永远不会被合并**，否则画面会糊成一片；如果 N 小到只剩强行合并一条路，程序会**宁可多留几个色也不糊图**；
- 实测对比（蓝色 6 个深浅阶占满全图 + 红色 2 格 + 绿色 2 格）：

  | 限到 | 旧算法（留最多 + 就近合并） | 新算法（聚类合并） |
  | --- | --- | --- |
  | 4 色 | `B3,B4,B5,B6` —— 四个几乎一样的蓝，**红绿被吃掉** | `B1,B5,R1,G1` —— 一浅一深两个蓝 + 红 + 绿，**都在** |
  | 3 色 | `B4,B5,B6` —— 仍然全蓝 | `B5,R1,G1` —— 阴影蓝 + 红 + 绿 |
  | 2 色 | —— | `B5,R1`（色数到极限，被迫再合并） |

- 性能：MARD 291 色的 200×200 随机图限到 16 色约 **47ms**，不卡手。

### 去掉四周背景，只留主体

生成面板上有「**去掉四周背景**」开关，编辑区也有个「**去四周背景**」按钮（随时可点，可 Ctrl+Z 撤销）。做法不是「把所有背景色的格子都删掉」—— 那样人物身上和背景同色的部分会被挖出洞。而是：

- **从最外圈往里做 4 邻接泛洪**，只有**和边缘连通**的同一个颜色才算背景；
- 所以**人物中间和背景同色的部分不会被误删**（它被主体包围，连不到边缘）；
- **中间起连接作用的部分照样保留**：脖子、头和身体的连接处、手臂和身体的连接处，它们夹在背景之间但属于主体；
- 只有一种颜色能当背景：**占到最外圈 40% 以上**的那个色。主体贴边不会被整片当背景；
- **精确同色才算背景，不做容差合并** —— 好处是不会啃掉主体边缘，坏处是抗锯齿留下的杂色点会留下来，用橡皮擦两下就行；
- 在**限色之后**执行，否则背景色可能已经被限色合并进主体色里，就分不出来了。

实测（80×60 白底红人的图，量化到 48×36）：1728 颗豆 → 461 颗，**背景 1267 格（73%）被清掉**，头 / 脖子 / 身体完整保留。

### 看图纸：格子里标色号 + 单选颜色高亮

出图之后最容易踩的坑是「这块到底该用什么色」。图纸预览上直接解决：

- **格子里写色号**：每个有豆子的格子中间标出 MARD 色号（`A01`、`M09`、`ZG6`…），跟用豆清单、跟店家色号一一对应，不用再对着色卡比颜色；
  - 默认就是**开着**的，在「③ 编辑与变换」里可随时关掉；
  - 字色按格子底色亮度自动切黑/白，浅色格子上不会白字看不见；
  - **格子太小会先缩短、再省略**，绝不会糊成一团：放得下就写 `H02`，只放得下两个字符就写 `02`，再小就干脆不写（宁可没有，也不要一堆看不清的残码）。缩小画布时会看到色号自动消失，放大回来又出现；
  - 导出的 PNG 和打印图纸走同一套规则，格距 30px 写完整色号，格距太小自动省略。
- **高亮当前色**：勾上「高亮当前色」后，画布上**只有当前选中的颜色是亮的**，其余颜色全部压暗，同色格子还会加一圈白描边把相邻的同一色块分开；
  - 「这个色一共用在哪几块」一眼就能看清，核对用豆清单、检查配色分布都好用；
  - 高亮时**只在亮着的格子上写色号**，避免整张图铺满文字；
  - 切换色卡上的颜色，高亮会跟着走；取消勾选立刻还原成正常预览；
  - 状态栏色号会显示「（高亮中）」，不会不知道自己在高亮模式里。
- **更顺手的入口：直接在「4. 用豆清单」里点任意一行** —— 一行就是「色块 + 色号 + 数量 + 库存 + 差额」，点它就等于：
  1. 把这个颜色设为当前色；
  2. 自动打开高亮，图纸上立刻只亮这个色。

  **再点同一行就取消高亮**，不用跑去勾开关。点另一行直接换过去，任何时刻只有一行是亮的（高亮行左侧有蓝色标记条）。这比先记色号、再去色卡里找那个色块快得多，尤其是 MARD 291 色的时候。

  库存输入框仍然照常可编辑，点输入框不会误触高亮。

## 打印图纸怎么才准确

- 打印窗口里**缩放必须选「100% / 实际大小」**，不要用「适合页面」，否则实物尺寸会偏小；
- 勾了 5 mm 豆径打印时，格距按 `5 × 96/25.4 ≈ 19px` 生成，**按 100% 打印就是 1:1 实物大小**，可以直接压在拼豆板上找位置；
- 图上每 **29 格**一条橙色分板线，对应一块 29×29 拼豆板；尺寸超出 A4 会自动分页，拼接时按坐标数字对齐；
- 图案太大时（>11000px）会自动降格距并提示，不会生成超大图。

## 自定义色卡格式

在「② 色卡」的折叠框里粘贴，或导入文件。支持三种写法：

```text
# 写法一：色号,HEX,名称（逗号/制表符/空格分隔都行）
A01,#FFFFFF,白
A02,#111111,黑
A03,#E03A2F,大红
```

```json
[{ "code": "A01", "hex": "#FFFFFF", "name": "白" }, { "code": "A02", "hex": "#111111", "name": "黑" }]
```

```text
# 写法三：只给 HEX，自动编号
#FF0000
#00FF00
```

以 `# 注释` 开头的行会被忽略；重复的 HEX 会自动去重；导入后即可当普通色卡使用，换色卡时会问你要不要把现有图案重新配色。

> 想按别的品牌色号（Hama / Artkal / Perler / 咪小窝…）配色：把这些品牌的色号-色值表按上面第一种写法粘进来即可。内置的「新手常用色卡」是按配色覆盖度手调的通用色，不代表任何品牌。

## 项目文件格式（`.json`）

```jsonc
{
  "app": "pindou-studio", "kind": "project", "version": 1,
  "grid":    { "w": 48, "h": 48, "rle": "<RLE+base64 的格子数据，-1 表示空格>" },
  "palette": { "id": "mard221", "name": "MARD 标准 221 色", "colors": [{ "code": "A01", "hex": "#FAF4C8", "name": "浅黄" }] },
  "stock":   { "#FAF4C8": 200 },
  "settings": { "gridW": 48, "dither": true, "beadMM": 5 }
}
```

## 已知边界 / 可以继续做

- 色号数据取自三份公开源中的一份，**源之间本身就有差异**（README 上文有实测差距），最终以实物色卡为准；
- 「自动选色」还没做：目前只能手填限色数量，还不能按图片自动挑出最优的 N 色 + 直接给出采购清单；
- 打印是「大图自动分页」，还没做**按分板线智能切页**（一页一块板、带页眉页码）；
- 没做多图批量转换、也没做 3D/立体拼豆的层视图；
- 编辑器没有选区/矩形/直线工具，暂时靠笔刷 + 填充；
- **手机手势只在 jsdom 里模拟验证过**（合成 pointer 事件），真机上的手感、抽屉动画、双指跟手程度没法在这里肉眼确认，建议装到手机上实际滑一遍；
- **触屏落笔有个故意的延迟**：手指按下时先不立刻画，等确认是单指拖动（或抬起）才落笔 —— 这是为了两根手指缩放时不会在图上留一个多余的点。鼠标/触控笔不受影响，按下即画；
- 还没做别的品牌（Artkal / COCO / 漫漫 / 盼盼 / 咪小窝）的一键切换，数据格式已支持，加个源即可。
